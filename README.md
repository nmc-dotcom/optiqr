# OptiQR

브라우저에서만 동작하는 QR 코드 디자이너. 스캔 품질 검사 내장.

**https://qr.holorado.me**

입력한 데이터는 서버로 전송되지 않고, 브라우저에 저장되지도 않습니다. 페이지를 여는 동안 어떤
외부 요청도 발생하지 않습니다(폰트 CDN, 분석 스크립트 포함).

[홀로라도 도구 모음](https://holorado.me)의 일부입니다.

---

## 기능

**데이터 타입** — URL, 텍스트, 이메일, 전화, SMS, WiFi, 명함(vCard), 위치(geo)

**디자인** — 단색/그라데이션, Dot 6종, Eye 4종, 중앙 로고, 배경, Quiet Zone, 크기, ECC 4단계

**내보내기** — PNG, SVG. 디자인 설정만 담은 JSON 프리셋 저장·불러오기

**스캔 품질 검사** — 이 도구의 차별화 지점. 설정을 바꿀 때마다 다음을 실시간으로 판정합니다.

- 명암비 (WCAG 상대 휘도 기준)
- 명암 반전
- Eye 색상과 배경의 대비
- Quiet Zone 규격 충족
- 로고로 인한 코드워드 손상량 (아래 "설계 결정" 참조)
- 기능 패턴 침범 (위치 검출·타이밍·정렬 패턴을 구분해 판정)
- ECC 수준 적정성
- 모듈 해상도 (내보내기 크기 ÷ 모듈 수)
- 데이터 과다로 인한 버전 상승

오류가 하나라도 있으면 점수를 39점으로 묶고 F등급을 매기며, 저장 버튼 위에 차단 배너를 띄웁니다.
읽히지 않는 QR에 "보통" 등급이 뜨면 사용자가 그대로 내려받기 때문입니다.

## 개발

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # dist/
npm run lint     # tsc --noEmit
npm test         # vitest run
```

**스택** — Vite 6 + React 19 + TypeScript 5.8 + Tailwind v4 (`@tailwindcss/vite`, 설정 파일 없음)

**배포** — Cloudflare Pages. `main` 브랜치 푸시 시 자동 배포. 빌드 `npm run build`, 출력 `dist`

### 구조

```
src/
├── lib/
│   ├── brand.ts            # 색상 토큰 + 폰트 스택
│   └── qr/
│       ├── types.ts        # 공용 타입 + FUNC_* 상수
│       ├── encoder.ts      # ISO/IEC 18004 인코더 (자체 구현)
│       ├── render.ts       # SVG 렌더러
│       ├── inspect.ts      # 품질 검사 엔진
│       ├── payload.ts      # 데이터 타입별 payload 빌더
│       ├── preset.ts       # 기본값 + 프리셋 검증(coerce)
│       └── encoder.test.ts
├── components/             # UI 프리미티브 + 패널
└── App.tsx                 # 상태 + 레이아웃
scripts/
├── threshold-check.ts      # 로고 임계값 실측 (CSV)
└── threshold-summary.ts    # 로고 임계값 실측 (요약, ASCII)
```

`lib/qr/*`는 React·DOM 코드를 포함하지 않는 순수 함수입니다. 테스트 가능성을 위한 제약입니다.

## 테스트

```bash
npm test
```

버전 1~40 × ECC 4단계 = 160개 조합을 전수 생성해 실제 디코더(`jsQR`)로 되읽고, 참조 구현
(`qrcode` 패키지)과 행렬을 대조합니다.

**이 테스트는 장식이 아닙니다.** 개발 중 ECC 블록 수 테이블의 H 레벨 버전 8 값이 5로 잘못
들어가 있었습니다(규격값 6). 이 조합으로 만든 QR은 어떤 기기로도 읽히지 않는데 화면에서는
완전히 정상으로 보였습니다. ECC H는 로고 사용 시 권장 기본값이고 v8은 vCard나 조금 긴 URL이
흔히 떨어지는 크기라, 실사용에서 충분히 마주칠 조합이었습니다.

인코더는 눈으로 검증이 불가능합니다. 인코더를 건드리는 모든 변경은 이 테스트를 통과해야 합니다.
특히 참조 구현 대조 테스트가 깨지면 출력 비트가 달라졌다는 뜻입니다.

### 로고 임계값 실측

```bash
npx tsx scripts/threshold-summary.ts
```

로고 크기를 5%에서 40%까지 올리며 검사기 판정과 실제 디코딩 성공 여부를 나란히 기록합니다.
검사기가 통과시켰는데 디코딩이 실패하는 행(`FALSE-SAFE`)은 **0이어야 합니다.**

## 설계 결정

되돌리기 전에 배경을 확인하세요. 대부분 시행착오를 거쳐 뒤집힌 결정입니다.

### QR 인코더를 직접 구현했고, 교체할 수 없습니다

품질 검사기가 인코더 내부의 두 정보를 직접 참조합니다.

- `cwMap[y][x]` — 각 모듈이 속한 코드워드 번호
- `funcMap[y][x]` — 기능 패턴 종류 (위치 검출 / 타이밍 / 정렬 / 포맷)

`qr-code-styling` 같은 라이브러리는 이 정보를 노출하지 않습니다. 렌더링만 라이브러리에
맡기면 인코더가 둘이 되어 검사 결과와 실제 그림이 어긋날 수 있고, 이 도구에서는 그게 가장
치명적인 버그입니다.

### 로고 손상은 면적이 아니라 코드워드 단위로 계산합니다

ECC의 "30% 복원"은 면적이 아니라 **코드워드 개수** 기준입니다. 원형 로고의 경계는 수많은
코드워드를 조금씩만 걸치면서 통째로 손상시키므로, 면적 비율로 판정하면 실제 손상을 크게
과소평가합니다.

실제 사례 — v3(29×29), ECC H, 로고 34% + 여백 6.5%

| 모델 | 판정 | 실제 |
|---|---|---|
| 면적 기준 | 22.1% < 30% → 안전, 89점/B | 스캔 실패 |
| 코드워드 기준 | 블록당 정정 한도의 약 145% → 오류 | 일치 |

`logoDamage()`가 실제 배치를 훑어 손상 코드워드를 세고, 인터리빙에 따라 블록별로 나눠
정정 한도(ECC 코드워드 ÷ 2)와 비교합니다. `safeLogoSize()`는 이분 탐색으로 안전한 최대
크기를 역산해 숫자로 제시합니다.

### 기능 패턴은 종류별로 판정합니다

위치 검출·타이밍·포맷 영역이 가려지면 디코더가 격자와 방향 자체를 못 잡으므로 오류입니다.
반면 내부 정렬 패턴은 하나 정도 가려져도 남은 패턴으로 격자를 외삽할 수 있어 주의로 처리합니다.

이 구분이 없으면 정렬 패턴이 정확히 중앙에 오는 버전(v10·v11 등)에서 5% 로고부터 오류가
뜹니다. 실측으로는 40%까지 읽힙니다.

### 히스토리를 저장하지 않습니다

이 도구가 다루는 게 WiFi 비밀번호, 명함의 개인 번호, 비공개 URL입니다. IndexedDB 히스토리와
URL 해시 직렬화 모두 폐기했습니다. 저장이 없으면 개인정보 처리 자체가 성립하지 않습니다.

대신 **디자인 설정만** 담는 JSON 프리셋을 파일로 주고받습니다. 입력 데이터는 포함되지 않습니다.

프리셋은 사용자가 편집할 수 있는 외부 입력이므로 `coerce()`가 알려진 키만 알려진 범위로 좁혀
받습니다. 로고는 `data:image/...;base64,` 형태만 허용합니다. 원격 URL을 허용하면 프리셋을
여는 것만으로 외부 요청이 나가 이 도구의 전제가 깨집니다.

### 외부 폰트 CDN을 쓰지 않습니다

Google Fonts import는 페이지를 여는 것만으로 외부 서버에 접속 기록을 남깁니다. Pretendard가
설치돼 있으면 사용하고, 없으면 OS 기본 한글 서체로 떨어집니다.

### 색상 토큰의 단일 출처는 JavaScript입니다

색상 값이 `<input type="color">`와 QR 렌더링에 실제 hex 문자열로 들어가야 합니다
(`var(--color-green)`을 컬러 피커에 넣을 수 없습니다). CSS와 JS 양쪽에 색을 두면 언젠가
어긋나므로 `src/lib/brand.ts`가 단일 출처입니다.

## Phase 1 완료 기준

- [x] 8종 데이터 타입 각각에서 실제 기기 스캔 성공
- [x] 입력·디자인 변경 시 재생성 버튼 없이 미리보기 즉시 갱신
- [ ] Dot 6종 × Eye 4종 조합에서 QR이 깨지지 않고, 로고 20% + ECC H 조합이 스캔됨
- [x] PNG·SVG 다운로드 동작, SVG를 브라우저에서 열었을 때 미리보기와 동일
- [x] 품질 검사가 명암비·로고·Quiet Zone·Eye 대비·ECC·모듈 해상도·데이터 과다를 실시간 판정
- [x] 의도적으로 나쁜 설정을 만들면 오류 등급이 뜨고 실제로도 스캔 실패
- [x] 로고 크기를 5%→40%로 올리며 검사기 판정과 실제 디코딩 결과 대조 (거짓 안심 0건)
- [ ] 위 항목을 실제 기기(iPhone·Android 기본 카메라)로 재확인
- [ ] 프리셋 저장 → 기본값 복귀 → 다시 불러오기 시 디자인 복원, 파일에 입력 데이터 없음
- [ ] 망가뜨린 프리셋 파일(범위 초과·타입 오류·원격 이미지 URL)을 불러와도 앱이 죽지 않음
- [x] 네트워크 탭에 외부 요청 0건
- [ ] 모바일 폭 375px에서 레이아웃 유지

7번째 항목이 이 도구의 차별화 주장이 성립하는지를 결정합니다. `jsQR` 기준으로는 통과했으나
실제 기기 대조가 남아 있습니다. jsQR이 실기기보다 관대할 수 있으므로, 그 결과가 나오기 전까지
`load` 임계값(0.7 / 1.0)과 정정 한도 계산은 조정하지 않습니다.
